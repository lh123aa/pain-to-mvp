# 首次真实使用：聊天女主播 0 卡——品类型关键词评论区无痛点，求助型才有密度

## 增量：首次真实使用（关键词「聊天女主播」）——0 卡诚实产出 + 关键词选型认知

### 事实
- e2e 完整跑通：发现 10 候选 → 爬 78 条评论 → 6/6 步 EXIT=0，88.5s（新关键词跨域，管线无断链）
- **0 张新卡**，非缺陷：78 条评论仅形成 1 个簇（size=3 < MIN_EVIDENCE=5），export 按"宁缺毋假"诚实跳过；scored/pains/dashboard 均正常重建
- 根因（数据侧，非代码侧）：10 个候选里 9 个评论 ≤10 条、3 个 discover 时 comment_count 就是 0（爬回 0 字节=真没有评论，非风控失败）；唯一有数据的视频（480167594，137 评论）贡献了唯一的簇，内容是抱怨B站推送机制，与域无关
- 唯一簇引文回溯正常（"为啥还是疯狂推送"等 3 条可溯源），但属B站产品抱怨，不构成"聊天女主播"域机会

### 认知（insight）
- **关键词选型决定数据密度**：品类型关键词（"聊天女主播"）的搜索结果偏擦边引流切片，观众评论区只有时间戳/玩梗/求软件名，无痛点讨论；求助型关键词（"独立开发者怎么接单"）搜索者自带痛点，评论区痛点密度高
- 要挖"聊天女主播"行业的机会，痛点人群是**主播/公会侧**而非观众侧——应换主播侧求助型关键词（"新人主播怎么开始""直播没人看怎么办""直播设备推荐"）

### 判定与口径
- 本轮不进 A4 窗口：PRD 25 行原文"**给定关键词** 10 次运行中 ≥9 次完整出卡不中断"——A4 窗口以"独立开发者"为准，仍 3/10
- 无卡 → 无校准记录，仍 8/20
- 工具"不许骗人"原则本轮得到正向验证：数据不足时 0 卡而非硬凑

### 风险 / 未决
- 发现排名靠后的候选多为擦边内容（标题可见），若换关键词后仍大量出现，考虑在 discover 层加域内质量过滤（暂不动手，等第二个真实关键词的数据再判断）
