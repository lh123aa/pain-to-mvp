# 阶段6工程收尾：#19 CI + #27回退陷阱长期解（隔离副本+字节断言两半）

## 增量：阶段 6 工程收尾 #19 CI + #27 回退陷阱长期解

### 决策
- #19 test.yml 只跑 pytest 单元套件，明确不跑 Makefile `make test`（后者是 B 站端到端爬取，需网络凭证+风控暴露，不进 CI）；yml 内留注释说明，防后人"顺手补全"
- #27 长期解拆两半：
  1. **隔离**：conftest 加 `workspace_clone` fixture（copytree 剔除 .git/vendor/data/docs/project-journal），两个跑 apply_fixes 的测试改在副本上执行（子进程 cwd=副本 → apply_fixes.ROOT 自动指向副本）——真实工作区零写入
  2. **响亮护栏**：新增 `test_canonical_four_match_fixes_overlays` 字节级断言 canonical 4 文件与 generators/fixes/ 一致——忘同步在测试红且报错直指 RK-0001，取代"静默回退丢工作"

### 问题与解法
- 故意不同步 RED 验证：Add-Content 给 cluster.py 加尾行 → 护栏测试红（报错含"忘了同步权威副本"）→ git checkout 还原 → 绿。护栏不是摆设
- 幂等测试原为进程内 importlib 调 apply_fixes.main()（ROOT 是模块常量指向真实树），改子进程跑副本内脚本绕开 monkeypatch ROOT 的侵入式方案

### 真实数字
- 全量 187 → **188 passed**（+1 护栏测试；原幂等测试改副本运行不改数量）
- 副本含 ~450 文件 copytree ×2 + 子进程 apply_fixes ×2，全量套件仍正常完成
- commit 162b6be

### 认知更新
- "防回退"有两种形态：**隔离**（测试不碰真实树，防丢工作）与**断言**（字节一致性守门，防忘同步）。只做隔离的话，忘同步要到手动跑生成器时才炸；两半合起来才把陷阱从"流程纪律"变成"测试红"
