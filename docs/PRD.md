# PRD — Pain-to-MVP 探矿仪

版本：0.1.0 ｜ 更新：2026-10-13 ｜ 状态：已确认（经 10 问问答定稿）

---

## 一、定位与用户

- **定位**：输入一个关键词，从真实平台评论区挖出可信痛点，输出可执行的机会卡片。
- **唯一用户**：项目所有者本人（自用工具）。
- **使用场景**：
  1. 验证手上已有项目的商业价值（评论里到底有没有人为它叫好/抱怨竞品）
  2. 发现值得动手的新需求（新机会卡片）
- **使用模式**：本地 Windows 命令行 + 浏览器看板，一次探一个细分方向。

> 推论：可靠性要求以「不产出假信息」为底线，而非「永不中断」。出错可以手动介入，但**不许骗人**（假评分、假闭环、静默降级都算骗人）。

## 二、成功指标（P6 真实案例验收标准）

跑完一轮真实关键词后，**同时**满足以下两条即判定验证通过：

1. **卡片可信率 ≥ 70%**：抽检当轮 top 机会卡片，「痛点在原始评论中有真实证据、且确为真需求」的比例 ≥ 70%。
2. **≥ 1 张卡片驱动实际验证动作**：至少一张卡片促使你做了真实动作（发内容 / 找目标用户聊 / 做落地页）。

工程底线（任何一轮都必须满足）：给定关键词 10 次运行中 ≥ 9 次完整出卡不中断。

- ❌ 自愈 / 自优化 / Journey 接回主流程：**代码保留、标注"未接线、不投入"**（当初判定为假闭环，重接需重新设计）
- ❌ 部署、发布、upstream PR、多人使用支持

## 四、非功能需求（NFR）

### 4.1 可靠性：严格可靠（fail-close）

- `robots.txt` 读不到 → **跳过该平台**，不允许 fail-open
- JSONL 坏行 → 跳过 + 警告，不崩溃
- discover 失败 → **绝不复用**上一轮的旧产物文件
- `data/` 产物全部 gitignore，不入库

### 4.2 性能与数据量级：小规模快跑

| 指标 | 预算 |
|---|---|
| 单关键词候选内容 | ≤ 20 条 |
| 单关键词评论 | ≤ 500 条 |
| 端到端耗时 | ≤ 10 分钟 |
| 聚类质量保证范围 | ≤ 2000 条评论 |

### 4.3 兼容性

Windows（win32）原生可跑，Python 3.11+，入口统一 UTF-8（`scripts/pipeline/encoding.py`）。

## 五、评分体系与校准机制

- **默认**：启发式（demand / feasibility 两维归一化）。
- **可选**：有 `OPENAI_API_KEY` 时 `--llm` 补全五维，**单轮 LLM 成本上限 ¥2**。
- **校准闭环**（每轮跑完必做）：
  1. 抽检当轮 top3 卡片，逐张标「真 / 假」
  2. 追加到 `data/calibration/calibration.jsonl`（含：卡片 ID、判断、理由、日期）
  3. 累计每满 20 条抽检，回看一次规则命中率，决定是否调 `pain_rules.SIGNALS` / 权重
- 规则或权重变更必须保留抽检记录作为回归依据。

## 六、接口契约

### 6.1 需求状态机（dashboard.json）

```
pending → discovering → crawling → mining → scoring → designing → done
   └─────────────── 任意状态 ────────────────→ dropped（终态）
```

- `status` 只允许上述枚举值；**单向流转**，不允许回退（要回退只能 `dropped` 后重开）
- `progress`：0-100，只增不减
- `dashboard.json` 顶层必须含 `schema_version`；schema 变更必须升版本号并同步本文档
- 校验落地见 OPEN_ISSUES（当前 `update_progress.py` 仍是自由字符串，待加校验）

### 6.2 各阶段产物

JSONL/JSON 产物（discovered / raw / pains / scored）的字段以
`references/tool-compatibility.md` 的标准格式为准；读取方必须容忍缺字段并给出明确报错，禁止裸 KeyError。

## 七、安全与密钥规范

- 所有凭证（`BILI_SESSDATA` / `OPENAI_API_KEY` / Reddit secret 等）统一写仓库根 `.env`（已 gitignore）
- 提供 `.env.example` 作为模板；**提交前检查清单：确认 `.env` 未入库**
- 代码读取 `.env` 的接线（python-dotenv）见 OPEN_ISSUES；接线前可用 shell 环境变量
- 合规红线：不绕验证码（如 v_voucher）、不破解登录、频率 ≤ 1 请求/秒、作者名脱敏

## 八、工程流程

- `feat/prospecting-fixes` 合并 `master` 后，版本从 **0.1.0** 起按 semver 计（废弃生成器时代的 5.x）

- 推 GitHub 后补 `test.yml`（push/PR 跑 pytest），见 OPEN_ISSUES
