## 1. 需求（证据）

### 1.1 核心痛点
**后端开发者想做垂直领域小程序，但前端只会 jQuery/AngularJS，缺一个「预设模板设计界面 → 自动生成前端代码 → 只管数据绑定」的工具。**

### 1.3 代表原话（匿名，可回溯）
- 「我是做后端的，想做一个有关垂直领域的微信小程序，前端只会 jquery 和简单的 angularJS，如果有一种工具可以让你基于预设的模板做界面设计，自动生成前端代码，你只需要关注怎么与后端做数据绑定，就爽了。」
- 「服务器一般选什么配置？服务器费用是否包含在开发费用里面？后期维护怎么搞，这一块感觉就比较麻烦。」
- 「一般人家开发 APP 的结局怎么样？有没有人全部身家去开发一个 APP？」

**关键洞察**：「太麻烦」是高频情绪词——用户缺的不是技术能力，是把前端工作**降维到数据绑定层**的工具。连"服务器费用算不算在开发费里"都要问 → 需要的是**打包方案**，不是零散工具。

## 3. MVP 方案（最小可验证）

**推荐形态**：模板/提示词库 —— 把「小程序常见界面」整理成预设模板 + 一键生成前端代码，用户只做数据绑定。

**最小交付物（Day 3 前做出）**：
1. 3 套高频小程序界面模板（列表/表单/详情），单文件 HTML
2. 每套配「数据绑定说明」：后端接口怎么对上前端字段
3. GitHub Pages 零成本托管，一个可点开的 demo URL

**技术栈（全免费）**：GitHub Pages + 单文件 HTML + 爱发电收款 + 金数据表单

## 6. 风险与止损（提前说清）

- **需求可能伪**：Day 2 访谈若 <70% 认可"前端是最大卡点"，立即停，不做到 Day 3
- **前端工具红海**：v0.dev / Cursor 已能做"描述生成前端"；本方案的差异点 = **小程序垂直 + 数据绑定说明**，若 Day 3 发现没有差异点 → 改方向
- **单点数据源**：本报告基于 B 站评论；若后续 B 站风控长期不可用，方法仍可迁移到知乎/小红书评论区（§5 复用逻辑不变）

**止损线**：7 天内 Day 4 首单 + Day 5 反馈都不达标（0 单 0 正面反馈）→ 停止投入本需求，回管线换下一个 S 档卡。**不追加投入、不"再试一个月"。**
