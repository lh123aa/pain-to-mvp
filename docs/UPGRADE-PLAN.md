## 0. 执行原则（监督依据）

1. **不阻塞优先**：凡不依赖 v_voucher 解锁的先做（报告层/信任层/交付层）；
2. **小步可验**：每任务先 v1（存量改造）再 v2（管线化）；v1 不等原机数据；
3. **测试门禁**：任何代码改动 → `PYTHONUTF8=1 pytest` 全绿（基线 **238**）+ 生成器产物抽查；
4. **不编数字**；合规红线（不绕风控/只爬公开内容/脱敏）继承；每完成一项 → journal 记录；涉及收入 → ledger 记账；
5. **价格纪律**：以 `PRICING-VALIDATION.md` 为唯一口径，变更需记录理由。

## 3. 监督机制

- **每轮开工**：读 `NEXT-ACTIONS.md` + 本表状态；**收工**：journal 追加 + 本表更新；
- **完成定义（DoD）**：交付物存在 + 验收标准逐条核过 + journal 有记录；代码类 = 测试全绿；
- **阻塞处理**：标 ⛔ + 写明原因与解锁条件（同步进 NEXT-ACTIONS"等待中"）；
- **节奏**：包 A 目标 2 周；每周五对照本表复查一次；
- **风险哨**：T3/T4 完成 7 天后仍 0 发布 / 0 反馈 → 触发**渠道复盘**（不是任务问题，是分发问题，对齐 MONETIZATION-EXECUTION 阶段 2 止损点）。
